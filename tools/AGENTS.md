# tools 目录规则

## 工具异常回执军规（用户定案 2026-11-06）

所有工具遇到非正常情况（异常返回、意外中断、超限、资源缺失）时，回执必须包含
「下一步的处理方案」——告诉 LLM 应该做什么（续跑/重试/换方式/询问用户），
而不是只陈述失败事实。LLM 看不到处理方案时会自行猜测处置（典型事故：子代理
失败后没有引导，LLM 第一时间不停原样重新派发任务，形成重派死循环）。

- 引导文案写进回执文本（Error/Note/Reason），不写进工具 Prompt——Prompt 是
  每轮都进 system 段的持久开销，只放「这是什么、参数怎么用」。
- Prompt 禁止与 Parameters 描述重复；禁止写 LLM 不具备概念的内部机制
  （如 daemon、轮询器、幂等状态机）。
- 引导方向遵循续跑优先原则：优先引导「向既有会话发起继续/重试」（保留进度
  自动修复），仅当无会话锚点或任务必须全新开始时才引导重新派发。
